# 私有默认作者档案

`gzh-design` 可从 Skill 安装目录中的 `.author-profile.json` 读取默认作者信息。该文件只用于本地排版，不属于可共享的 Skill 内容。

## 安装副本

在已安装的 `gzh-design` Skill 目录中执行：

```bash
cd "<gzh-design 安装目录>"
cp .author-profile.example.json .author-profile.json
```

然后编辑 `.author-profile.json`，填入自己的署名和一句话简介。不要直接修改示例文件，以便后续更新时继续保留可复制的通用模板。

## Schema

文件必须是合法 JSON，并包含两个非空字符串字段：

```json
{
  "name": "你的署名",
  "bio": "一句话简介"
}
```

`name` 和 `bio` 去除首尾空白后都非空，档案才有效。

## 署名优先级

署名来源按以下顺序解析：

1. 文章中已有的明确署名，或用户在本次请求中明确提供的署名。
2. 有效的私有 `.author-profile.json`。
3. 不输出署名。

文章中已有的签名必须保留，不得再从请求或默认档案生成重复签名。用户本次只提供部分作者信息时，仅使用已提供内容，不补写缺失字段，也不输出任何作者占位符。

## 隐私与回退

- `.author-profile.json` 含真实作者信息，必须保持私有，**绝对不得提交到版本库**。
- `.author-profile.example.json` 只能保留通用示例，允许纳入版本控制，不得写入真实姓名或简介。
- 文件不存在、JSON 无效、字段缺失、字段类型错误或任一字段为空时，均视为没有有效默认档案。
- 无有效署名来源时，删除整个作者介绍/签名区域，只保留所选主题的 footer CTA；不得输出 `{{作者名}}`、`{{简介}}` 或其他作者占位符。
- 无效 JSON 不得阻塞排版；忽略该档案、继续生成内容，并在交付说明中指出档案无效且已省略签名区域。
